[대표 개선점]
1. 비상 정지 우선순위
   "비상 정지하고 사진 찍어"에서 emergency_stop만 생성했다. v0.1에서 확인된
   안전 명령 이후 추가 명령 생성 문제가 해결됐다.

2. 기수 고정 표현
   "기수를 고정한 채 5시 방향으로 0.6미터 이동해"에서
   face_direction=false를 정확히 생성했다. relative_position 완전 일치도도
   50%에서 100%로 상승했다.

3. 숫자와 속도 파라미터
   회전 각도 75도와 회전 속도 초당 15도를 각각 yaw_deg와 yaw_speed_dps로
   정확하게 분리했다.

4. 복합 명령
   사진 두 장을 1.5초 간격으로 촬영한 뒤 착륙하는 명령과, 사진 촬영 후 이동
   경로를 역순으로 복귀하는 명령을 올바른 순서와 파라미터로 생성했다.

5. 비드론 요청 거부
   일반 감정 질문과 수학 과제를 invalid로 처리하고 지정된 JSON 형식을 지켰다.

[학습 후 남은 핵심 문제]
1. 일반 방향과 시계 방향 함수 선택
   "정면으로 0.45미터 이동"을 move_drone(forward)가 아니라
   move_clock_direction(clock_hour=12)으로 생성했다.

2. 명령 중복 생성
   "초속 1.4미터로 위로 2.2미터 상승해"에서 동일한 상승 명령을 두 번 만들고,
   첫 번째 명령에는 speed_mps를 누락했다.

3. 필수 거리 임의 생성
   "사진 두 장 찍고 뒤로 물러나"에서 사용자가 말하지 않은 distance_m=2를
   생성했다. "12시 방향으로 이동해"에서도 distance_m=0을 생성했다.

4. 회전 방향 안내 오류
   반시계 방향 회전 각도를 물어야 하는 상황에서 "오른쪽으로 몇 도"라고
   안내했다. status와 commands 구조가 맞더라도 의미가 반대다.

5. 홈 복귀 문구 불일치
   "홈까지 가줘"를 clarification_required로 처리해 상태는 개선됐지만,
   return_home과 recall 중 무엇을 원하는지 묻지 않고 특정 표현을 다시 말하도록
   요구했다.

6. unsupported 안내의 구체성 부족
   조건부 비전, 원형 비행, 예약·반복 실행을 unsupported로 구분하는 데는
   성공했지만 모두 유사한 "조건부 명령" 메시지를 사용했다. 기능별 실패 이유를
   구체적으로 설명할 필요가 있다.

[평가 지표 해석 시 주의사항]
- Test 데이터가 20개로 작아 샘플 하나가 전체 지표 5%p를 좌우한다.
- basic_single과 vision_language는 각각 1개뿐이므로 유형별 0% 또는 100%를
  일반화하기 어렵다.
- ambiguous_or_impossible은 구조와 상태가 개선됐어도 메시지 문자열 차이 때문에
  exact_match가 낮게 계산될 수 있다.
- 의미가 같은 안내 문장도 문자열이 다르면 완전 일치 실패가 된다. 따라서
  exact_match와 구조적 지표를 함께 봐야 한다.
- 현재 로그에는 정확도 형태의 train accuracy 또는 validation accuracy가 없고,
  학습 과정은 step loss, train_loss, eval_loss로 기록됐다. 정확도 지표는 별도의
  Test 20개에 대한 파인튜닝 전후 평가 결과다.

[dataset_v0.3 및 다음 작업]
1. 필수 인자가 누락된 단일·복합 명령을 대폭 보강하고 임의 값 생성을 금지한다.
2. forward/backward/left/right/up/down 표현과 시계 방향 표현을 분리 학습한다.
3. 속도, 거리, 각도, 고도 수치를 서로 다른 인자로 정확히 연결하는 대조 사례를
   추가한다.
4. clarification_required 메시지의 의미 평가와 문자열 완전 일치를 분리한다.
5. unsupported 유형별로 비전 부재, 경로 계획 미지원, 예약 실행 미지원 등 정확한
   사유를 출력하도록 보강한다.
6. Test 데이터를 최소 50~100개로 늘리고 유형별 샘플 수를 균형 있게 구성한다.
7. emergency_stop 단독 명령, 필수값 누락, 안전 범위는 모델 외 실행 코드에서도
   강제로 검증한다.

[종합 판단]
dataset_v0.2 파인튜닝은 정상적으로 완료됐고 v0.1보다 Schema, Status, 명령,
파라미터 및 완전 일치 지표가 추가 개선됐다. 특히 비상 정지 우선순위와 기수
고정 표현은 이번 버전의 뚜렷한 성과다.

다만 전체 완전 일치는 50%이고 Test가 20개에 불과하다. 필수 인자 누락 시 임의
값을 생성하는 문제와 의미상 반대인 안내 문구도 남아 있으므로, 현재 어댑터를
실제 드론 실행 계층에 바로 연결하기보다는 dataset_v0.3 보강과 별도의 안전 정책
검증을 먼저 적용하는 것이 적절하다.
