[대표 개선점]
1. 일반 방향 함수 선택
   "정면으로 0.45미터 이동"을 v0.2의 move_clock_direction이 아니라
   move_drone(direction=forward)로 정확히 생성했다.

2. 기수 고정 표현
   "기수를 고정한 채 5시 방향으로 0.6미터 이동해"에서 face_direction=false를
   정확히 생성했고 relative_position 완전 일치 100%를 유지했다.

3. 비상 정지 우선순위
   "비상 정지하고 사진 찍어"에서 emergency_stop만 생성해 안전 우선순위를
   유지했다.

4. 수치 명령
   시계 방향 75도와 초당 15도를 yaw_deg, yaw_speed_dps로 정확히 분리했다.

5. 비드론 요청 거부
   감정 질문과 수학 과제를 invalid로 처리하고 지정 JSON 형식을 유지했다.

[학습 후 남은 핵심 문제]
1. recall 명령 회귀
   "사진 찍고 이동 경로를 거꾸로 따라 복귀해"를 take_photo+recall로 처리하지
   않고 clarification_required로 판단했다. v0.2에서 성공했던 항목이 v0.3에서
   다시 실패한 회귀다.

2. 동일 이동 명령 중복
   "초속 1.4미터로 위로 2.2미터 상승해"에서 동일한 상승 명령을 두 번 생성하고
   첫 번째 명령에는 speed_mps를 누락했다.

3. 필수 거리 처리의 불안정성
   "사진 두 장 찍고 뒤로 물러나"는 clarification_required로 개선됐지만,
   "12시 방향으로 이동해"에서는 사용자가 말하지 않은 distance_m=3을 생성했다.

4. 회전 방향 안내 오류
   반시계 방향 회전 각도를 질문하면서 "오른쪽으로 몇 도"라고 안내해 의미가
   반대로 출력됐다.

5. 홈 복귀 안내의 내부 함수명 노출
   return_home과 recall의 차이를 묻는 방향은 맞지만 사용자 메시지에 내부 함수명을
   그대로 노출했다. 자연어 표현으로 안내하는 편이 적절하다.

6. unsupported 분류 오류
   조건부 비전과 원형 비행은 unsupported로 처리했지만, 예약·반복 실행 명령은
   clarification_required로 잘못 분류했다.

7. 안내 메시지 완전 일치 문제
   vision_language를 올바르게 unsupported로 판단했어도 메시지가 기대 문구와 달라
   exact_match는 0%다. 의미 평가와 문자열 평가를 분리할 필요가 있다.

[평가 지표 해석 시 주의사항]
- Test 데이터가 20개라 샘플 하나가 전체 지표 5%p를 바꾼다.
- basic_single과 vision_language는 각 1개뿐이므로 유형별 0% 또는 100%를
  일반화하기 어렵다.
- 전체 완전 일치는 메시지 문자열 차이까지 실패로 계산하므로 구조적 정확도보다
  낮게 나타날 수 있다.
- 현재 로그에는 train accuracy 또는 validation accuracy가 없으며, 학습 과정은
  step loss, train_loss, eval_loss로 기록됐다. 정확도 지표는 별도 Test 20건의
  파인튜닝 전후 평가 결과다.
- train_loss가 v0.2의 0.1517에서 0.1603으로 소폭 상승했지만 eval_loss는
  0.1287에서 0.1146으로 하락했다. 단일 실행의 작은 차이만으로 모델 우열이나
  과적합을 확정해서는 안 된다.

[dataset_v0.4 및 다음 작업]
1. v0.3에서 회귀한 take_photo+recall 사례를 재보강한다.
2. 속도와 거리가 함께 있는 이동 명령에서 단일 명령만 생성하도록 보강한다.
3. 거리 누락 시 시각 등 다른 숫자를 거리로 사용하지 않고 질문하도록 보강한다.
4. 시계·반시계 방향과 좌·우 표현의 대응을 대조 학습한다.
5. 예약·반복 실행을 unsupported로 일관되게 처리한다.
6. 사용자 메시지에 return_home, recall 같은 내부 함수명 대신 자연어를 사용한다.
7. Test 데이터를 50~100개 이상으로 늘리고 유형별 샘플 수를 균형 있게 구성한다.
8. exact_match 외에 status/commands/arguments/message 의미 유사도를 분리 평가한다.
9. 실제 실행 전 emergency_stop 단독성, 필수 인자, 안전 범위 및 입력에 없는 숫자
   생성을 코드에서도 검증한다.

[종합 판단]
dataset_v0.3 파인튜닝은 정상적으로 완료됐고 JSON 및 Schema 검증은 Test 20건
모두 성공했다. 일반 방향 함수 선택이 개선됐으며 명령·파라미터 정확도도 v0.2보다
각 5%p 상승했다.

반면 Status 정확도는 5%p 하락했고 전체 완전 일치는 50%로 정체됐다. v0.2에서
성공했던 recall 복합 명령이 다시 실패하는 회귀도 확인됐다. 따라서 v0.3은 구조적
안정성은 향상됐지만 의미 정확도가 전면적으로 개선된 버전은 아니다. v0.4에서는
회귀 사례와 필수값 누락 시 숫자 임의 생성 문제를 우선 보강해야 한다.
