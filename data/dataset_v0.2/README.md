# 드론 명령 데이터셋 v0.2

한국어 드론 명령을 모델이 정해진 JSON 명령으로 바꾸도록 학습·평가하는 데이터셋이다.

- `train.jsonl`: 학습용 400개
- `validation.jsonl`: 학습 중 검증용 20개
- `test.jsonl`: 최종 시험용 20개

각 줄에는 사용자 질문(`user`)과 기대 정답(`assistant`)이 하나씩 들어 있다. 기대 정답은 프로젝트의 드론 명령 스키마를 따라야 한다.
## 상태 판단 기준

- `accepted`: 현재 지원하는 드론 명령이고 실행에 필요한 정보가 충분하다. `commands`에 명령을 순서대로 넣는다.
- `clarification_required`: 드론 명령이지만 필요한 거리·높이·각도 등이 빠졌다. 숫자를 추측하지 않고 `commands`는 비워 둔 채 `message`로 되묻는다.
- `unsupported`: 드론 관련 요청이지만 현재 지원하지 않는 기능이나 조건부 동작이 필요하다. `commands`는 비워 둔다.
- `invalid`: 드론 명령으로 이해할 수 없는 질문이다. `commands`는 비워 둔다.
## 명령 구분 기준

- 비상 정지가 포함된 요청은 `emergency_stop`을 우선하며, 뒤따르는 이동·촬영 명령을 추가하지 않는다.
- `cancel`은 아직 실행하지 않은 명령의 취소이고, `emergency_stop`은 즉시 동작을 멈추라는 요청이다.
- “홈으로 바로 복귀”는 `return_home`, “왔던 경로를 되짚어 복귀”는 `recall`이다. 복귀 방식이 불분명하면 되묻는다.
- “기수를 고정한 채 몇 시 방향으로 이동”은 `face_direction: false`, “그 방향을 바라보고 이동”은 `face_direction: true`다.
## 데이터 사용과 검토

- `train.jsonl`만 모델 학습에 사용한다. `validation.jsonl`은 학습 중 검증, `test.jsonl`은 학습 후 평가에 사용한다.
- 별도로 보관한 평가 질문 30개와 정답표는 학습 데이터에 넣지 않는다.
- JSON 스키마 검사와 동일 문장 중복 검사를 통과했더라도, 명령의 의미와 정답이 맞는지는 사람이 검토해야 한다.
- 모델이 틀린 사례를 확인한 뒤 필요한 유형만 다음 버전에 보완한다.
